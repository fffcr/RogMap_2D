# 3D 地图 → 2D 可通过性地图 · 研究方案

> 目标：把 `rog_map`（SUPER 版）的 3D 占据图 / ESDF，投影成一张 2D 通过性地图，用于地面机器人（RoboMaster）的 2D 导航。
>
> 本文是"方案选型 + 算法细节"，配套的动手步骤见 [《3D转2D_练手指导文档.md》](3D转2D_练手指导文档.md)。

---

## 0. 先纠正一个术语（重要，避免走弯路）

你提到"3D ESKF"，但在 `rog_map` 目录里**不存在 ESKF**。两个词只差一个字母，含义完全不同：

| 缩写 | 全称 | 是什么 | 在本仓库的位置 |
|------|------|--------|----------------|
| **ESKF** | Error-State Kalman Filter 误差状态卡尔曼滤波 | **状态估计**：融合 IMU+激光，输出里程计位姿 | `BJLG_openSource/src/perception/Point-LIO`（`esekfom`/IKFoM） |
| **ESDF** | Euclidean Signed Distance Field 欧氏符号距离场 | **地图**：每个体素存"到最近障碍的距离"，`esdf_map` | `rog_map/include/rog_map/esdf_map.h` |

- 你的"3D→2D 融合"针对的是**地图**（占据图 `prob_map` / 距离场 `esdf_map`），**不是**那个滤波器。
- 滤波器（ESKF）保持不动，它只是地图的上游数据源（里程计）。
- 下文统一说"3D 地图"，不再叫它 ESKF。

## 1. 目标的形式化定义

机器人有固定高度（车体，从地面到车顶约 0.5~0.8 m）。对每个水平位置 $(x, y)$，考察高度区间 $[z_{low}, z_{high}]$（= 车体扫掠空间）：

$$
\text{type}_{2D}(x,y) =
\begin{cases}
\text{OCCUPIED},  & \exists z \in [z_{low}, z_{high}],\ \text{type}(x,y,z) = \text{OCCUPIED} \\
\text{UNKNOWN},   & \text{无 OCCUPIED，且} \exists z,\ \text{type}(x,y,z) = \text{UNKNOWN} \\
\text{KNOWN\_FREE}, & \text{其余（整段都已知空闲）}
\end{cases}
$$

这就是你说的"**某个高度范围内都无障碍物才是真正可通过的**"。本质是沿 Z 轴做一次 **any/max 归约（reduction）**。

### 两个必须想清楚的设计点

1. **"未知"怎么算？** 保守做法是把 UNKNOWN 也当占据（安全），激进做法当可通过（探索更积极）。ROG-Map 里用 `unk_thresh` 参数控制"未知占比多高算未知"（`counter_map.h`），你的 2D 层也应该保留一个类似阈值。
2. **地面本身是障碍。** RoboMaster 场景里地面点云是巨大障碍。ROG-Map 用 `virtual_ground_height` 把"地面以下"当地面处理、`virtual_ceil_height` 把"天花板以上"当顶处理（详见 §2）。你的高度区间应取在 `[virtual_ground_height, virtual_ceil_height]` 之内（通常就是车体高度那段）。

## 2. 现有代码已经有什么（别重复造轮子）

### 2.1 虚拟地面 / 天花板（Z 轴裁剪，已存在）
- 参数：`config.hpp:211-212`（`virtual_ground_height`、`virtual_ceil_height`）。
- 射线裁剪：`prob_map.cpp:723-738`——射线打到地面/天花板时，把命中点投影到对应平面，且不再标记为 hit。
- 查询裁剪：`prob_map.cpp:106-134`（`isOccupied/isUnknown/isKnownFree(pos)`）——`pos.z()` 超出 `[virtual_ground, virtual_ceil]` 直接判 OCCUPIED。

**结论**：它只做了"两端裁剪"，没有把中间整段高度"压成一个 2D 值"。这正是你要补的部分。

### 2.2 CounterMap 的"融合"逻辑（逻辑原型，已存在）
`counter_map.h:80-96` 的 `getGridType(hash_id)`：

```cpp
// 1) 任一子体素占据 → 占据
// 2) 无占据但未知数 >= unk_thresh → 未知
// 3) 否则 → 已知空闲
```

这就是你要的融合语义。但它融合的是 **3D 立方块**（`inflation_ratio^3` 个细体素 → 1 个粗体素，用于膨胀图和 ESDF 的降分辨率），**不是**"沿 Z 的柱子"。

**结论**：融合逻辑现成、方向现成，你缺的只是"沿 Z 柱子的投影层"。

## 3. 候选方案对比

| 方案 | 思路 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A. Z 柱投影层（late fusion）** | 3D 地图不动，新增查询/缓存层，对每个 (x,y) 沿 Z 归约 | 完全命中你的想法；改动最小；可增量验证；保留 3D 信息（以后能改高度区间） | 每格要扫 N_z 层（可缓存/增量解决） | **推荐** |
| B. 配置级近似 | 把 `map_size` 的 z 压到车体高度那一薄层 + 调 virtual_ground/ceil | 几乎不改代码 | 仍不是真正 2D；丢高于车体的信息（如悬空物能否钻过） | 不推荐 |
| C. 点云级早投影 | 喂地图前先按 Z 过滤点云 | 实现简单 | 丢信息、raycast 仍 3D、不是真正 2D 网格 | 可作 A 的补充 |
| D. 另写原生 2D costmap | 从零写 2D 栅格 | 结果最干净 | 放弃 ROG-Map 的 raycast/ESDF/滑动窗口，重复劳动最多 | 不适合练手阶段 |

**推荐：方案 A**。它和你"把一定高度区间内的占据去做融合"的直觉一致，且最利于你拿这个项目练手（改动聚焦、每步可验证）。

## 4. 核心算法（方案 A 细节）

### 4.1 占据 2D 归约

```cpp
GridType Projection2D::getGridType2D(double x, double y) {
    bool has_unknown = false;
    for (double z = z_low_; z <= z_high_; z += resolution_) {
        Vec3f p(x, y, z);
        GridType t = prob_map_->getGridType(p);   // 或直接读 occupancy_buffer_
        if (t == OCCUPIED)  return OCCUPIED;      // 任一占据 → 占据
        if (t == UNKNOWN)   has_unknown = true;
        if (t == OUT_OF_MAP) continue;
    }
    return has_unknown ? UNKNOWN : KNOWN_FREE;    // 整段空闲才可通过
}
```

- 若配置 `treat_unknown_as_occupied = true`，把最后一行换成 `return has_unknown ? OCCUPIED : KNOWN_FREE`。
- 复杂度：每格扫 $N_z = \lceil (z_{high}-z_{low})/res \rceil$ 层。车体 0.6 m、分辨率 0.1 m → 6 层，可接受。

### 4.2 ESDF 2D 距离（可选，给规划/轨迹优化用）

2D 距离 = 该柱子内到最近障碍的距离：

$$
d_{2D}(x,y) = \min_{z \in [z_{low}, z_{high}]} d_{3D}(x,y,z)
$$

注意 `esdf_map` 的 `getDistance` 只对**已更新的局部更新盒**有效（`updateESDF3D` 的 `update_local_map_min_i_/max_i_`），查询前要判断是否在更新盒内，否则给个保守大值。

### 4.3 性能与增量刷新

- **最简版（先验证正确性）**：不做缓存，每次查询现场扫 Z。适合先跑通。
- **缓存版（正式）**：加一张 2D 栅格（大小 = 3D 地图的 x×y），
  - 随 `SlidingMap::mapSliding` 一起滑动（复用 `sliding_map.cpp` 的逻辑）；
  - 只在 raycast 的**局部更新盒**内重新计算 Z 柱，盒外复用旧值（因为盒外没变）。

## 5. 推荐落地路径（与指导文档一一对应）

1. **加配置**：`robot_height`（或 `projection_z_min/z_max`）、`treat_unknown_as_occupied`、2D 是否启用。
2. **加查询函数**：在 `ProbMap` 里加 `getGridType2D(x, y)`，先做无缓存版，用现有可视化验证正确性。
3. **加缓存 2D 栅格层**：随滑动地图一起滑动 + 局部更新盒内增量刷新。
4. **发布 2D 占据栅格**：在 ROS1 封装里发布 `nav_msgs/OccupancyGrid`，喂给 `move_base`（`nav_msgs` 已在依赖里，无需新增）。
5. **（可选）ESDF 2D 距离场**：`min`-over-band，供走廊/轨迹优化使用。
