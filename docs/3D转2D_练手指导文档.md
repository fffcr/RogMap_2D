# 3D 地图 → 2D 距离场 · 练手指导文档

> 适用：`rog_map`（独立 ROS1 节点，`rog_map/include/rog_map/`）。
>
> 路线（**本文档的主线**）：
>
> ```
> 3D 点云/地图
>     ↓
> 计算 3D ESDF          → 每个 (x,y,z) 存到最近障碍的 3D 欧氏距离
>     ↓
> 对每个 (x,y) 取 min_z  → d_2D(x,y) = min_z d_3D(x,y,z)
>     ↓
> 得到 2D 距离场
>     ↓
> 喂给 2D 规划器
> ```
>
> **本文档已按这条路线重写。** 上一版走的是"柱分类 → 2D mask → 2D EDT"，两条路线的取舍见 §1.5。
> 本文只讲"怎么一步步做"，每阶段都有**验收标准**，做完一阶段再进下一阶段。

## 0. 全局流水线（先记住这张图）

```
   3D 点云
     │
     │  ProbMap::updateProbMap
     ▼
   occupancy_buffer_  (ProbMap, log-odds, 分辨率 = rog_map/resolution)
     │
     │  inf_map_ (CounterMap: 任一子体素占据 → 占据)
     ▼
   ┌─────────────────────────┐
   │ ESDFMap::updateESDF3D   │  ← 已有的，esdf/enable = true 才跑
   │ 输出 distance_buffer     │
   └─────────────────────────┘
     │
     │  signed，单位米：自由为正，障碍内为负
     │  只刷新 [odom ± esdf.local_update_box/2]
     ▼
   ┌─────────────────────────┐
   │ 【你要加的】min_z 归约    │  d_2D(x,y) = min over z ∈ 扫描带
   └─────────────────────────┘
     │
     ▼
   2D 距离场 dist_m_  (w × h，有符号，米)
     │
     ├──> nav_msgs/OccupancyGrid   (给 move_base / costmap)
     └──> sensor_msgs/PointCloud2  (给 rviz 看，按 intensity 上色)
```

**一句话**：2D 距离场不需要另算一次欧氏距离——**3D ESDF 里已经算过了**，沿 z 取 min 就是 2D 距离（§1.1 给出证明）。这条路线比"重建一张 2D mask 再跑 2D EDT"少了整整一个距离变换，代码量小得多。

### 0.1 三个前提：不满足则整条流水线失效

先看这张表，它比代码重要。

| # | 前提 | 不满足的症状 | 怎么满足 |
|---|------|-------------|---------|
| 1 | **地面不能是 3D ESDF 里的障碍** | 开阔平地 `d_2D ≈ 0.1~0.3`（= 扫描带下沿到地面的距离），整张图一片"低值"，墙的横向距离完全看不出来 | 把 `virtual_ground_height` 抬到真实地面上方（§1.2） |
| 2 | **扫描带必须落在 ESDF 更新盒之内** | 离机器人稍远处 `d_2D` 是**陈旧值**，机器人一走就整片跳变 | 带 ⊂ `odom ± esdf/local_update_box/2`（§1.3） |
| 3 | **`esdf/enable` 必须打开** | `esdf_map_` 是空指针，`getDistance` 直接段错误 | 改 yaml（§3） |

前提 1 是这条路线**唯一真正会翻车的地方**。原因见 §1.2：`getDistance` 是带符号的，而地面本身就是障碍，所以只要你把地面高度扫进带内，min 就会被地面主导。这也是上一版文档 §1 把"min/max 归约"判为错误的原因——**但那个结论只在"地面留在图里"的前提下成立**。把地面从图里拿掉之后，min 归约就是对的，而且是最简洁的解法。

## 1. 为什么"3D ESDF → min_z"是对的

这一节是选型依据。**如果你只读一节，读 §1.2。**

### 1.1 min_z 就是 2D 距离（证明）

`distance_buffer` 是**带符号**的 3D 欧氏距离场。`esdf_map.cpp` 里分三趟算出来：

| 趟 | 代码位置 | 做什么 |
|----|---------|--------|
| 第 1 趟 | `esdf_map.cpp:105-163` | 占据格喂 `0`、自由格喂 `max` → 正距离，乘 `esdf_resolution` 后写进 `distance_buffer` |
| 第 2 趟 | `esdf_map.cpp:165-222` | 反过来（占据格喂 `max`、自由格喂 `0`）→ 到最近**自由**格的距离，覆盖进 `tmp_buffer1_` |
| 合并 | `esdf_map.cpp:225-236` | `if (tmp_buffer1_[idx] > 0.0) distance_buffer[idx] += (-tmp_buffer1_[idx] + sc_.resolution);` |

结果：

| 体素 | `getDistance()` |
|------|-----------------|
| 自由 | `+` 到最近障碍的距离（米） |
| **占据** | `res − 到最近自由格的距离 ≤ 0`（**负的**） |
| 半自由（`inv_mask` 距离恰为 1 格的占据边界） | 恰好 `0` |

现在设扫描带 $Z=[z_{lo}, z_{hi}]$，障碍集合 $\mathcal{O}$。对固定 $(x,y)$：

$$
\min_{z\in Z} d_{3D}(x,y,z)
= \min_{z\in Z}\ \min_{o\in\mathcal{O}} \|(x,y,z)-o\|
= \min_{o\in\mathcal{O}}\ \min_{z\in Z}\ \|(x,y,z)-o\|.
$$

对单个障碍点 $o=(o_x,o_y,o_z)$：

$$
\min_{z\in Z} \|(x,y,z)-o\| = \sqrt{(x-o_x)^2+(y-o_y)^2+\big(\mathrm{dist}(o_z,Z)\big)^2},
\qquad \mathrm{dist}(o_z,Z)=\begin{cases}0, & o_z\in Z\\ |o_z - \text{最近带沿}|, & o_z\notin Z\end{cases}
$$

于是

$$
\boxed{\ d_{2D}(x,y)=\min\Big(\underbrace{\min_{o:\,o_z\in Z} d_{xy}(o)}_{\text{带内障碍的水平距离（精确）}},\ \underbrace{\min_{o:\,o_z\notin Z}\sqrt{d_{xy}(o)^2+\Delta z(o)^2}}_{\text{带外障碍 + 垂直惩罚}}\Big)\ }
$$

**两条结论**：

1. **带内障碍贡献的距离是精确的 2D 欧氏距离。** $o_z\in Z$ 时 $\Delta z = 0$，$\min_z$ 取在 $z=o_z$，结果就是 $d_{xy}(o)$。所以 $d_{2D}$ 在带内障碍面前**就是**真正的 2D ESDF——`|∇_{xy} d| = 1`，梯度干净，可以直接喂轨迹优化。
2. **带外障碍不会产生假障碍，只加一个垂直惩罚。** $o$ 在带上方的横梁，$\Delta z>0$，贡献一个**正值** $\sqrt{d_{xy}^2+\Delta z^2}$。所以"车顶上方有梁但车能过"的位置 `d_2D > 0`（可通过），只是值偏小 → 规划器把它当"谨慎区"而不是"禁行区"。**这个行为恰好是对的。**

**符号**：$d_{2D}<0 \iff \exists z\in Z$ 使 $(x,y,z)$ 落在某障碍内 $\iff$ 柱子在带内与障碍相交 $\iff$ **车过不去**。min 保号，不需要额外判断。

> **所以扫描带 $Z$ 的物理含义就是车的扫掠包络**。$z_{lo}$ = 车底盘离地高度，$z_{hi}$ = 车顶高度 + 余量。带内相交 = 撞车。这是整条流水线的设计基准。

### 1.2 前提一：地面不能进 3D ESDF（**唯一会翻车的地方**）

假设地面在 $z = z_g$。RoboMaster 场景里地面点云是**巨大**的障碍，而且——

**地面点在 `distance_buffer` 里就是障碍格（负值）**，只要它进了图。那么对带上方的自由点 $(x,y,z\in Z)$：

$$
d_{3D}(x,y,z) \approx z - z_g \quad(\text{到正下方地面的距离})
$$

于是 $\min_{z\in Z} d_{3D} = z_{lo} - z_g$，**一个和墙毫无关系的常数**。开阔平地、墙边、箱子旁边，`d_2D` 全是同一个值。**整张距离场被地面污染成一个常数场，完全失效。**

这不是精度问题，是**符号被地面占满了**：靠近地面的自由格 `getDistance ≈ 0`，于是整张图 `d_2D ≈ 0` → 2D 规划器看到的是"处处贴墙"。

#### 怎么解决：把地面从图里裁掉

**用 `virtual_ground_height`。** `raycastProcess` 里有这段（`prob_map.cpp:725-740`）：

```cpp
bool update_hit{true};
// 1.3) filter for virtual ceil and ground
if (p.z() > cfg_.virtual_ceil_height) {
    update_hit = false;
    const double dz = p.z() - cur_odom.z();
    const double pc = cfg_.virtual_ceil_height - cur_odom.z();
    p = cur_odom + (p - cur_odom).normalized() * pc / dz;   // 投影到顶面
}
else if (p.z() < cfg_.virtual_ground_height) {
    update_hit = false;
    const double dz = p.z() - cur_odom.z();
    const double pc = cfg_.virtual_ground_height - cur_odom.z();
    p = cur_odom + (p - cur_odom).normalized() * pc / dz;   // 投影到地面
}
```

关键在 **`update_hit = false`**：出带的点被"抬"到虚拟平面上，**而且不计为命中** → 不写占据，只进 `raycasting_cloud` 用于沿射线做 free 更新（`prob_map.cpp:779-790`）。

所以：**把 `virtual_ground_height` 设到真实地面**上方**，地面点云就永远进不了 `occupancy_buffer_` → 进不了 `inf_map_` → 进不了 `esdf_map_` 的占据计数 → `distance_buffer` 里没有地面。** 前提 1 满足，min 归约就是干净的。

#### ⚠️ 两个必须知道的手调坑

**坑 1：`virtual_ground_height` 会被量化两次，设进去的值 ≠ 生效值。**

`Config::resetMapSize()` 末尾（`config.hpp:406-427`，`ORIGIN_AT_CORNER` 分支）先算：

```cpp
inf_virtual_ground_height_id_g = static_cast<int>(floor(virtual_ground_height / inflation_resolution)) + inflation_step;
virtual_ground_height = inf_virtual_ground_height_id_g * inflation_resolution + 0.5 * inflation_resolution;
```

然后 `ProbMap::initProbMap` 又把它**向下取整**到 ProbMap 分辨率（`prob_map.cpp:63-67`）：

```cpp
posToGlobalIndex(cfg_.virtual_ground_height, sc_.virtual_ground_height_id_g);
cfg_.virtual_ground_height = sc_.virtual_ground_height_id_g * cfg_.resolution;
```

**实测**（`SUPER/super_planner/config/static_dense.yaml` 的真实参数：`resolution: 0.05`、`inflation_resolution: 0.1`、`inflation_step: 3`、`virtual_ground_height: -0.1`）：

| 步 | 计算 | 结果 |
|----|------|------|
| 输入 | yaml 写的 | `-0.1` |
| `resetMapSize` | `floor(-0.1/0.1) + 3 = -1 + 3 = 2`，`2*0.1 + 0.05` | `0.25` |
| `initProbMap` | `floor(0.25/0.05) = 5`，`5*0.05` | **`0.25`** |

**所以 yaml 里写 `-0.1`，实际生效的是 `+0.25`。** 别猜，**看启动日志打印的那一行**。

**坑 2：抬太高会连带裁掉矮障碍。**

`virtual_ground_height` 是一条**全局水平面**，它分不清"地面"和"地面上 0.2 m 的一个箱子"。抬到 0.25 m 意味着所有低于 0.25 m 的东西都从图里消失了。对 RoboMaster（车高 0.3~0.5 m）这是可接受的——0.25 m 以下的障碍本来就爬得过去——但你要**心里有数**：这个标量同时在控制"地面干不干净"和"矮障碍看不看得见"，两者不可兼得。

> **为什么不用别的办法移地面？**
>
> - **点云预过滤**（喂地图前把 `z < min_z` 的点丢掉）：这是 BJLG 走的路（`BJLG_openSource/src/perception/rog_map/src/rog_map_ros/cloud_registered_crop_filter.cpp:180-188`，`point.z < min_z` 直接滤掉）。同样有效，但多一处上游处理，且**丢掉了 free-space 更新**——被滤掉的点不再参与"沿射线标 free"，机器人脚边那片自由空间会一直停在 UNKNOWN。`virtual_ground_height` 把点抬到平面上继续做 free 更新，信息利用更充分。
> - **调 `scan_z_min_rel` 绕开地面**：这是**上一版文档的做法**，也是上一版被判错的原因。绕开之后，判据 4（薄表面）就永远不触发；而在本路线里，绕开地面等于带内没有任何东西能贡献水平距离，`d_2D` 依旧是常数场。**扫描带必须包含地面高度以上到车顶的整段，地面靠 `virtual_ground_height` 裁，不靠扫描带绕。**
>
> **补充：UNKNOWN 怎么算？** 本路线里 `distance_buffer` 只有"到最近占据格的距离"，不区分 UNKNOWN。要保守（未知当障碍）就调 `esdf.unk_thresh`（默认 `0.70`）：`CounterMap::isUnknown(hash)` 是 `unknown_cnt[hash] >= unk_thresh`——**注意是 `>=`，`unk_thresh = 1.0` 时"全部子体素未知"才算未知**（`counter_map.h:115-117` 的注释专门说明了这个 `=` 的必要性）。想让未知更保守就调低它。

### 1.3 前提二：扫描带必须落在 ESDF 更新盒之内

`updateESDF3D` **不是**全图重算，只刷新机器人周围一小块（`esdf_map.cpp:97-101`）：

```cpp
Vec3i min_esdf = cur_odom_i - half_local_update_box_i_;
Vec3i max_esdf = cur_odom_i + half_local_update_box_i_;
update_local_map_min_i_ = min_esdf.cwiseMax(local_map_bound_min_i_);
update_local_map_max_i_ = max_esdf.cwiseMin(local_map_bound_max_i_) - Vec3i::Ones();
```

`half_local_update_box_i_` 由 `esdf/local_update_box` 算出（`esdf_map.cpp:52-53`：`posToGlobalIndex(local_update_box, ...)` 然后 `/2`）。实测 yaml 用 `[5,5,3]` → **xy 各 ±2.5 m，z ±1.5 m**。

**盒外的 `distance_buffer` 是陈旧值**，而且更糟：

> `ESDFMap::resetLocalMap()`（`esdf_map.cpp:66-70`）**只重置计数器、不清 `distance_buffer`**
> ```cpp
> void ESDFMap::resetLocalMap() {
>     std::fill(md_.unknown_cnt.begin(), md_.unknown_cnt.end(), md_.sub_grid_num);
>     std::fill(md_.occupied_cnt.begin(), md_.occupied_cnt.end(), 0);
> }
> ```
> 滑窗走过之后，`distance_buffer` 里留的是**上一个地方**的距离值，物理上毫无意义。沿 z 取 min 会把这些脏值当成有效值扫进来。

**所以扫描带必须夹在更新盒里**，每一步都要夹：

```cpp
const double z_lo = std::max(odom_z + cfg_.projection.scan_z_min_rel, box_min.z());
const double z_hi = std::min(odom_z + cfg_.projection.scan_z_max_rel, box_max.z());
if (z_hi < z_lo) return MinZResult{};     // 带和盒无交集 → 无有效值
```

**xy 也要夹**：`box_min.x() <= x <= box_max.x()`，否则同理会读到脏值。

#### 那 2D 场能看多远？

`esdf/local_update_box` 的 xy 那一半**直接决定 2D 场的有效范围**。默认 `[5,5,3]` → 只有 ±2.5 m，对 2D 规划器太小。

调大它，但要付代价：`updateESDF3D` 的复杂度是 **O(盒体积)**，三个方向各跑一趟 EDT，**每帧都跑**（挂在 `updateProbMap` 末尾，`prob_map.cpp:354-356`）。

| `local_update_box` | 体素量 @ 0.1 m | 评价 |
|--------------------|---------------|------|
| `[5, 5, 3]` | 50×50×30 = 75 k | 现有实测值，太小 |
| **`[12, 12, 1.6]`** | **120×120×16 = 230 k** | **推荐起点**，±6 m / z ±0.8 m |
| `[20, 20, 1.6]` | 200×200×16 = 640 k | ±10 m，开始吃力 |
| `[20, 20, 3]` | 200×200×30 = 1.2 M | 基本等于全图重算，会掉帧 |

**关键优化：z 那一维不用给大。** 车的扫掠包络只有 ~0.6 m（§1.1），带外只需要一点点垂直余量来给悬空物算惩罚。`1.6` 就够了，而默认的 `3` 白白多花一倍算力。**z 是最便宜的削减维度。**

> 如果 ±6 m 还是不够（2D 全局规划），正确做法是**降频**：`updateESDF3D` 不必每帧跑，累积 N 帧跑一次，或者把 2D 场的刷新放到独立定时器里跑 5~10 Hz。**不要靠继续加大盒子。** 这一步放到 §7 阶段 5 再做。

### 1.4 前提三：带外障碍的行为（说清楚，别误会）

把 §1.1 的结论说成人话：

| 场景 | 带内相交？ | `d_2D` | 对不对 |
|------|-----------|--------|--------|
| 开阔平地，离墙 2 m | 否 | `≈ +2.0` | ✅ 精确 |
| 实心竖墙 | **是** | `< 0` | ✅ 挡住 |
| 低横梁，离地 0.2 m（车高 0.5） | **是** | `< 0` | ✅ 挡住 |
| 高横梁，离地 0.8 m（车高 0.5） | 否 | `≈ +0.2`（垂直惩罚） | ✅ 通过，但临近 → 规划器会谨慎 |
| 天花板以下、带以上什么都没有 | 否 | 到墙的水平距离 | ✅ |

**注意第 4 行**：`d_2D` 在悬空物正下方会变得**比真实 2D 距离小**（因为带了垂直分量）。它不会变负（不产生假障碍），但会让优化器在梁下看到"很近"。这是**保守方向**，可以接受；想消掉的话把带顶 `scan_z_max_rel` 抬到梁上方即可（代价是车顶以上的矮空间不再被检查）。

### 1.5 和上一版路线（分类 + 2D EDT）的关系

两条路线解决的是**同一个问题**，但切法不同：

| | 上一版：柱分类 → 2D mask → 2D EDT | **本版：3D ESDF → min_z** |
|---|---|---|
| 判"地面可过" | 柱扫描 + 六条判据（`height_delta ≤ 0.25 → THIN_SURFACE`） | `virtual_ground_height` 把地面推出图外 |
| 判"低横梁可钻" | `HOLLOW_TUNNEL` 判据（填充率 ≤ 0.6） | 带顶 `scan_z_max_rel` 低于横梁 → 带内无相交 |
| 2D 距离从哪来 | 一张 mask，跑两趟 Felzenszwalb EDT | **3D ESDF 里已经有，取 min** |
| 新增文件 | 3 组（`projection_layer` / `esdf_utils` / `field_layer`） | **1 组**（`projection2d`） |
| 每帧开销 | `w×h×N_z` 全量柱扫描 + 两趟 2D EDT | `N_z` 次 `getDistance` + 一次 min（**复用已有的 3D EDT**） |
| 前提 | 六条判据的阈值要在真机上标定 | **`virtual_ground_height` 要标定**（§1.2 坑 2） |
| 已知弱点 | 阈值敏感；薄片/实体的区分靠"高度跨度+填充率"两个统计量近似，斜面和阶梯容易误判 | 全局水平面分不清"地面"和"地面上的矮箱"；带外障碍给的是带垂直惩罚的近似距离 |
| 参考实现 | **BJLG 生产版走的就是这条**（`projection_layer.cpp`，`CellType`/`ColumnStats`/`surface_height_delta_max`，逐条可 diff） | BJLG **没有**——它的 `projection_layer` 里**没有 `min_z` 也没有 `getDistance`** |

**本版为什么更好（对你的场景）**：

1. **代码量小一个量级。** 3D EDT 已经有人写好了、测过了；你只需要写一个 min。
2. **梯度性质更好。** §1.1 证明了带内距离是精确 2D 欧氏距离，`|∇d|=1`。分类路线里 mask 是二值的，EDT 出来的场在 `argmin` 切换处有折角。
3. **只有一个手调标量**（`virtual_ground_height`），而不是六个阈值。

**本版的代价，你要接受**：`virtual_ground_height` 是全局常数，**分不清"地面"和"地面上的矮箱"**。分类路线能靠 `height_delta` 把两者分开——但它的判据也要靠 `scan_z_min_abs` 包含地面才触发，同样有标定负担，只是把负担从一个标量摊到了六个。

> 两条路线**不冲突**：将来如果"矮箱被裁掉"成了实际问题，可以在本路线之上再叠一层分类（用 `occupancy_buffer_` 而不是 3D ESDF 来判断柱子的高度跨度），专门救回 `virtual_ground_height` 以下的矮障碍。**先把本路线跑通再考虑。**

## 4. 阶段 2：min_z 归约（纯函数 + 单元测试，工作量最小、最关键）

### 4.1 新文件：`include/rog_map/projection2d.h`

```cpp
#pragma once

#include <algorithm>
#include <cmath>
#include <cstdint>
#include <limits>
#include <mutex>
#include <vector>
#include <Eigen/Core>

namespace rog_map {

/// 一个 XY 柱子在扫描带内的归约结果（调试 / 可视化都靠它）
struct MinZResult {
    double distance = 0.0;   ///< d_2D，米，有符号
    bool   valid    = false; ///< 柱内是否取到过有效采样（false = 带与更新盒无交集）
    bool   blocked  = false; ///< 是否存在 d_3D < 0 的采样（该柱不可通过）
    int    n_sampled = 0;    ///< 有效采样数
    int    n_blocked = 0;    ///< 其中 d_3D < 0 的数量
};

/// 归约配置
struct MinZConfig {
    double scan_z_min_rel = -0.05; ///< 扫描带下沿，相对 odom 的 z（米）
    double scan_z_max_rel =  0.60; ///< 扫描带上沿，相对 odom 的 z（米）
    double max_distance   =  6.0;  ///< 正距离截断上限
    double min_distance   = -3.0;  ///< 负距离截断下限
    bool   clamp_distance = true;
    double inflation_radius = 0.0; ///< 整体外推，等效给障碍加半径
    double far_distance   = 10.0;  ///< 带内无任何有效采样时的兜底值
};

/// ── 纯函数：对一个柱子的 3D 距离序列取 min ──
/// 单元测试只测它。不碰地图、不碰索引，纯逻辑。
inline MinZResult reduceMinZ(const std::vector<double> &col, const MinZConfig &cfg) {
    MinZResult r;
    double best = std::numeric_limits<double>::max();

    for (const double d : col) {
        if (!std::isfinite(d)) {
            continue;                       // 无效采样直接跳过，不污染 min
        }
        ++r.n_sampled;
        if (d < 0.0) {
            ++r.n_blocked;
        }
        best = std::min(best, d);
    }

    if (r.n_sampled == 0) {
        r.distance = cfg.far_distance;
        r.valid    = false;
        return r;
    }

    r.valid   = true;
    r.blocked = (r.n_blocked > 0);

    // inflation：整体外推（障碍侧的负值也随之更深）
    double v = best - cfg.inflation_radius;
    if (!std::isfinite(v)) {
        v = cfg.far_distance;
    }
    if (cfg.clamp_distance) {
        v = std::clamp(v, std::min(0.0, cfg.min_distance), std::max(0.1, cfg.max_distance));
    }
    r.distance = v;
    return r;
}

/// ── 2D 距离场容器（只存结果 + 坐标换算，不做计算）──
class Field2D {
public:
    void update(int width, int height, double resolution, const Eigen::Vector2d &origin,
                std::vector<double> dist_m, std::vector<uint8_t> occupied);

    /// 世界坐标查询。dist 正值自由、负值障碍内。越界返回 false。
    bool evaluate(const Eigen::Vector2d &pos, double &dist) const;

    int width()  const { return width_; }
    int height() const { return height_; }
    double resolution() const { return resolution_; }
    double maxDistance() const { return max_distance_; }
    const Eigen::Vector2d &origin() const { return origin_; }
    const std::vector<double>   &distances() const { return dist_m_; }
    const std::vector<uint8_t>  &occupied()  const { return occ_; }

private:
    int width_ = 0, height_ = 0;
    double resolution_ = 0.0, max_distance_ = 0.0;
    Eigen::Vector2d origin_ = Eigen::Vector2d::Zero();
    std::vector<double>  dist_m_;
    std::vector<uint8_t> occ_;   ///< 1 = blocked（d_2D < 0），0 = 可通过
    mutable std::mutex mutex_;
};

}  // namespace rog_map
```

### 4.2 新文件：`src/rog_map/projection2d.cpp`

```cpp
#include <rog_map/projection2d.h>
#include <stdexcept>

namespace rog_map {

void Field2D::update(int width, int height, double resolution, const Eigen::Vector2d &origin,
                     std::vector<double> dist_m, std::vector<uint8_t> occupied) {
    if (width <= 0 || height <= 0 || resolution <= 0.0) {
        throw std::invalid_argument("Field2D::update: invalid grid metadata");
    }
    const size_t expected = static_cast<size_t>(width) * static_cast<size_t>(height);
    if (dist_m.size() != expected || occupied.size() != expected) {
        throw std::invalid_argument("Field2D::update: size mismatch");
    }

    double mx = 0.0;
    for (const double d : dist_m) {
        mx = std::max(mx, d);
    }

    std::lock_guard<std::mutex> lock(mutex_);
    width_ = width; height_ = height; resolution_ = resolution; origin_ = origin;
    max_distance_ = mx;
    dist_m_.swap(dist_m);
    occ_.swap(occupied);
}

bool Field2D::evaluate(const Eigen::Vector2d &pos, double &dist) const {
    std::lock_guard<std::mutex> lock(mutex_);
    if (width_ <= 0 || height_ <= 0) {
        return false;
    }
    const int x = static_cast<int>(std::floor((pos.x() - origin_.x()) / resolution_));
    const int y = static_cast<int>(std::floor((pos.y() - origin_.y()) / resolution_));
    if (x < 0 || x >= width_ || y < 0 || y >= height_) {
        return false;
    }
    dist = dist_m_[static_cast<size_t>(y) * static_cast<size_t>(width_) + static_cast<size_t>(x)];
    return true;
}

}  // namespace rog_map
```

> **`evaluate` 用 `floor` 而非 `round`**：和 `ORIGIN_AT_CORNER` 下 `SlidingMap::posToGlobalIndex` 的约定一致（`floor(pos/res)`）。如果你编译时定义了 `ORIGIN_AT_CENTER`，这里要改成 `round`，否则会和地图**整体错半格**。

```cpp
MinZResult ProbMap::queryCell2D(const double &x, const double &y) const {
    MinZResult r;
    if (!cfg_.projection.enable || !cfg_.esdf_en || !esdf_map_) {
        return r;                                     // valid = false
    }

    Vec3f box_min_d, box_max_d;
    esdf_map_->getUpdatedBbox(box_min_d, box_max_d);

    // ① xy 必须在更新盒内（盒外是陈旧值，见 §1.3）
    if (x < box_min_d.x() || x > box_max_d.x() ||
        y < box_min_d.y() || y > box_max_d.y()) {
        return r;
    }

    // ② 扫描带 = odom 相对带 ∩ 更新盒 z 范围
    const double z_lo = std::max(cur_odom_.z() + cfg_.projection.scan_z_min_rel, box_min_d.z());
    const double z_hi = std::min(cur_odom_.z() + cfg_.projection.scan_z_max_rel, box_max_d.z());
    if (z_hi < z_lo) {
        return r;
    }

    // ③ 再确认落在 ESDF 的局部地图内（getHashIndexFromPos 越界会算错但不报错）
    if (!esdf_map_->insideLocalMap(Vec3f(x, y, 0.5 * (z_lo + z_hi)))) {
        return r;
    }

    // ④ 沿 z 采样
    const double dz = cfg_.esdf_resolution;           // ← 用 ESDF 的分辨率，不是 sc_.resolution
    std::vector<double> col;
    col.reserve(static_cast<size_t>((z_hi - z_lo) / dz) + 1);
    for (double z = z_lo; z <= z_hi + 1e-9; z += dz) {
        col.push_back(esdf_map_->getDistance(Vec3f(x, y, z)));
    }

    return reduceMinZ(col, cfg_.projection);
}
```

**三个容易写错的地方**：

1. **`dz` 必须用 `cfg_.esdf_resolution`**，不是 `sc_.resolution`。两者默认是 0.2 和 0.1（实测 yaml 是 0.1 和 0.05）。用错会让采样点落在体素边界上反复横跳。
2. **`getDistance(Vec3f)` 内部走 `getHashIndexFromPos`，越界不报错**（`sliding_map.h:127`），只会算出"错误但合法"的 hash 读到别的格子。所以 ①②③ 三道夹逼**一道都不能省**。
3. **`getDistance` 返回的可能是陈旧值**，即使夹在更新盒里也不保证是"这一帧"的——`updateESDF3D` 只在 `batch_update_counter` 到点时才更新地图（`prob_map.cpp:342-349`），而 ESDF 更新在它之后（`:354-356`）。实测 yaml 的 `batch_update_size` 决定这个错位有多大。**这是可接受的**（错开一帧），但你要知道它存在。

**（c）整图构建**：

```cpp
void ProbMap::buildField2D() {
    if (!cfg_.projection.enable || !cfg_.esdf_en || !esdf_map_) {
        return;
    }

    Vec3f box_min_d, box_max_d;
    esdf_map_->getUpdatedBbox(box_min_d, box_max_d);

    const double res = cfg_.esdf_resolution;
    const int w = static_cast<int>((box_max_d.x() - box_min_d.x()) / res) + 1;
    const int h = static_cast<int>((box_max_d.y() - box_min_d.y()) / res) + 1;
    if (w <= 1 || h <= 1) {
        return;
    }
    const Eigen::Vector2d origin(box_min_d.x(), box_min_d.y());

    const size_t n = static_cast<size_t>(w) * static_cast<size_t>(h);
    std::vector<double>  dist_m(n, cfg_.projection.far_distance);
    std::vector<uint8_t> occ(n, 0U);

    for (int j = 0; j < h; ++j) {
        for (int i = 0; i < w; ++i) {
            // 取格心（与 ORIGIN_AT_CORNER 的 floor 约定对齐）
            const double x = origin.x() + (i + 0.5) * res;
            const double y = origin.y() + (j + 0.5) * res;
            const MinZResult r = queryCell2D(x, y);
            const size_t idx = static_cast<size_t>(j) * static_cast<size_t>(w) + static_cast<size_t>(i);
            dist_m[idx] = r.distance;
            occ[idx]    = (r.valid && r.blocked) ? 1U : 0U;
        }
    }

    field_.update(w, h, res, origin, std::move(dist_m), std::move(occ));
}

**D1 平地测试 —— 本方案最重要的一条**

```
1. 车放开阔平地，静止，等地图稳定 3 秒
2. 在 updateProbMap 末尾临时打印：
     auto r = queryCell2D(cur_odom_.x(), cur_odom_.y());
     printf("cell2D: valid=%d blocked=%d d=%.3f n_sampled=%d n_blocked=%d\n",
            r.valid, r.blocked, r.distance, r.n_sampled, r.n_blocked);
3. 期望：valid=1, blocked=0, d ≈ (到最近墙的真实距离)，n_blocked = 0
4. 再打印离车 1 m / 2 m 处的值，应能看到 d 随距离单调增加
```

**`d` 是个小常数（0.1~0.3）而不是到墙的距离 → 逐条排查：**

| 先查 | 怎么查 | 结论 |
|------|--------|------|
| ① **地面还在图里吗** | 按 §3.3 的循环扫 `evaluateEDT`，看低处 `d3D` 是否趋近 0 | **是** → 回 §1.2，`virtual_ground_height` 抬到地面上方 |
| ② **采样带有没有落到地面上** | 打印 `z_lo`；对比 `z_lo - cur_odom_.z()` 和 `scan_z_min_rel` | `z_lo` 被 `box_min_d.z()` 夹住了（带比盒子还低）→ 说明扫描带跑出更新盒 → 加大 `esdf/local_update_box` 的 z |
| ③ **`dz` 用错了** | 打印 `cfg_.esdf_resolution` 和 `sc_.resolution` | 两者不相等就对了；如果你打印出来相等，检查 yaml 里 `esdf/resolution` 有没有生效 |
| ④ **`esdf/enable` 其实是 false** | 打印 `cfg_.esdf_en` | false → `queryCell2D` 直接返回 `valid=0` |

**D2 墙体测试 —— 顺便标定距离精度**

```
1. 车正对一面墙，量出真实距离 D（0.3 / 0.5 / 1.0 / 2.0 m 各一次）
2. queryCell2D(车前 D 处) → 期望 ≈ D ± esdf_resolution
3. 四组 (真实距离, 测得距离) 画出来 → 应是斜率 1、过原点的直线
```

- 斜率不是 1 → `dz` 或 `res` 用错了（和 `sc_.resolution` 混了）
- 截距不为 0 → 有常数偏移，查 `inflation_radius` 是否非 0，或地面还没裁干净
- 整体偏大 → 检查 `max_distance` 是不是把值截断了

**D3 横杆测试 —— 验证"带外障碍产生正值而非假障碍"**

```
摆一根横杆，离地高度 h；设车高 H = 0.4，scan_z_max_rel = 0.60
  h = 0.2（带内相交）    → 期望 blocked=1, d < 0
  h = 0.8（带上方，车能过）→ 期望 blocked=0, d ≈ h - scan_z_max_rel = 0.20（垂直惩罚）
从 h = 0.0 扫到 h = 1.0，步长 0.05，记录 blocked 翻转的那一点
```

**翻转点应≈ `scan_z_max_rel`（相对地面）。** 如果 `h > 车高` 时仍然 `blocked=1`，说明 `scan_z_max_rel` 设得比车高高太多 → **这是会误判为不可通过的那类错误**，直接撞车的方向相反（过度保守），但会让车绕远路甚至无路可走。反过来如果 `h` 明显低于车高时 `blocked=0` → **车会去钻钻不过的洞，这是会撞车的错误**，必须把 `scan_z_max_rel` 调到 `≥ 车高 + 余量`。

> **这一条是本方案的"胜负手"**，对应上一版的"判据 4"。它不成立的话整条流水线没意义。

**D4 滑动一致性**

```
让车走一段（触发 mapSliding），对同一个世界坐标 (x,y) 反复查询
  sliding 前后结果应一致（更新盒边缘一圈除外 —— 那里数据被清掉了）
```

不一致 → 检查 `getUpdatedBbox` 的 `origin` 是否每帧都取（**`esdf_map_` 自己也会 `mapSliding`**，见 `prob_map.cpp:303-305`；只要你每次都调 `getUpdatedBbox` 而不是缓存它，就是对的）。

**D5 梯度检查（跑优化器之前必做）**

```
在障碍附近取 3×3 邻域，中心差分算 ∂d/∂x、∂d/∂y
  未饱和区：期望 |∇d| ≈ 1        （§1.1 证明带内距离是精确 2D 欧氏距离）
  饱和区（超出 max_distance）：|∇d| = 0 属正常
  更新盒边缘：|∇d| 会突然变 0（数据被夹断），属正常
```

障碍附近 `|∇d|` 明显偏离 1 → 采样步长 `dz` 太粗（3D 距离在 z 上采样不够密），或 `resolution` 换算错了。**优化器对梯度比对距离敏感得多**，这个测试比 D2 更能提前暴露问题。

4. 和 `/rog_map/esdf`（3D 切片）并排看：`proj2d_sdf` 应该在墙前给出**更大的**距离值——因为 3D 切片在 `robot_z - 0.5` 那层，容易被地面拉低；min_z 已经不受地面影响。**这个对比就是本方案相对"直接拿 3D ESDF 单层切片"的收益。**

## 7. 阶段 5：性能与增量

阶段 3-4 每帧都在跑 `updateESDF3D` + 全量 `buildField2D`。这一步做性能。

### 7.1 先量，别猜

```cpp
TimeConsuming t_esdf("updateESDF3D", false);   // 已经有（esdf_map.cpp:83）
esdf_map_->updateESDF3D(pos);
double dt_esdf = t_esdf.stop();

TimeConsuming t_proj("buildField2D", false);
buildField2D();
double dt_proj = t_proj.stop();

// 每 30 帧打一次，别刷屏
static int cnt = 0;
if (++cnt % 30 == 0) {
    printf("[2D] esdf=%.2fms  proj=%.2fms  grid=%dx%d\n",
           dt_esdf, dt_proj, getField2D().width(), getField2D().height());
}
```

**预期**（`local_update_box = [12,12,1.6]`、`esdf_resolution = 0.1`、10 Hz）：

| 项 | 量级 | 备注 |
|----|------|------|
| `updateESDF3D` | **几 ms ~ 十几 ms** | 120×120×16 = 230 k 体素 × 3 趟 EDT。**这是大头** |
| `buildField2D` | **< 1 ms** | 120×120 = 14.4 k 格 × 16 次 `getDistance` = 230 k 次数组访问 |

**所以优化重点在 `updateESDF3D`，不在你自己的代码。** 这也是本路线的一个隐含优势：你的新增代码几乎不花时间。

### 7.2 `updateESDF3D` 的降频（最有效的一招）

`updateESDF3D` 不必每帧跑。在 `ProbMap` 里加个计数器：

```cpp
int esdf_skip_cnt_{0};
...
if (cfg_.esdf_en) {
    // 每 N 帧更新一次 3D ESDF；N=1 就是每帧
    if (++esdf_skip_cnt_ >= std::max(1, cfg_.esdf_update_interval)) {
        esdf_skip_cnt_ = 0;
        esdf_map_->updateESDF3D(pos);
    }
}
```

对应 yaml 加 `esdf/update_interval: 3`。**代价**：2D 场最多滞后 N 帧。对 10 Hz 的规划器，N=3 → 300 ms 滞后，**偏大**了；N=2 是常用的折中。**先量出实际耗时再定**——如果只有 2 ms，根本不用降频。

### 7.3 减少 min 的采样数（次要）

`queryCell2D` 每个柱子要采 `(z_hi - z_lo)/esdf_resolution ≈ 0.65/0.1 ≈ 7` 次。7 次里其实**只要一次负值就能提前返回** `blocked=1`（因为 min 一旦为负就确定不可通过，不需要知道负多少）。加个提前退出：

```cpp
for (double z = z_lo; z <= z_hi + 1e-9; z += dz) {
    const double d = esdf_map_->getDistance(Vec3f(x, y, z));
    if (!std::isfinite(d)) continue;
    ++r.n_sampled;
    if (d < 0.0) {
        ++r.n_blocked;
        r.blocked = true;
        // ⚠️ 不能直接 break！后面可能还有更负的值，d_2D 的数值会被 --inflation_radius
        //    和 clamp 影响。只在"你确定不需要精确负值"时才 break。
    }
    best = std::min(best, d);
}
```

> **但注意**：如果你把 d_2D 喂给优化器，**精确的负值是有用的**（障碍内部的梯度方向）。所以这个提前退出**只适合纯占据栅格发布那条路**，不适合距离场那条路。**默认别加。**

### 7.4 关于增量：**本路线不需要 dirty column**

上一版方案里"dirty column 增量刷新"是必需的（因为它要重建 2D mask）。**本路线不需要**，原因有两个：

1. **min_z 是只读归约**，没有中间状态要维护。每次 `buildField2D` 就是重读一遍 `distance_buffer`。
2. **距离场是全局量**——3D ESDF 里任意一个体素变了，整张 2D 场的距离都可能变。任何"只重算某几列"的增量都会给规划器留下过期距离。**上一版文档自己也承认了这一点**（"EDT 那一步不要增量"）。

**所以阶段 5 只做两件事：降频 + 量耗时。别做增量，省下的时间不如给 `updateESDF3D` 降频。**

> 如果以后真的要增量，正确的粒度是**跟随 `esdf_map_` 的更新盒**：盒外的 2D 格子直接复用旧值，盒内全量重算。这比 dirty column 简单得多，而且和 ESDF 自己的"局部更新"语义天然对齐。

### 7.5 阶段 5 验收标准

1. 用 §7.1 的计时打点，记录 `updateESDF3D` 和 `buildField2D` 各自耗时。
2. 降频前后，**`buildField2D` 的输出逐格比对**（同一帧的 `getField2D().distances()`）应当一致——因为它们读的是同一份 `distance_buffer`，只是频率不同。**对不上说明有别的 bug。**
3. `esdf/update_interval` 调到 1（每帧）确认拉满也能跑，再调回折中值。

## 9. 常见坑

1. **地面没裁干净（头号坑）。** 症状：`d_2D` 在平地上是个 0.1~0.3 的小常数。**排查顺序见 §5.4 D1 的表格。** 别忘了 `virtual_ground_height` 会被量化两次，yaml 写的值不是生效值（§1.2 坑 1）。
2. **索引越界不报错。** `getHashIndexFromPos` / `getHashIndexFromGlobalIndex` 对越界输入只会算出"错误但合法"的 hash，读到别的格子（`sliding_map.h:124-129` 有注释说明）。`queryCell2D` 里的三道夹逼（更新盒 xy、更新盒 z、`insideLocalMap`）**一道都不能省**。
3. **`dz` 用了 `sc_.resolution` 而不是 `cfg_.esdf_resolution`。** 两者默认 0.1 vs 0.2（实测 yaml 0.05 vs 0.1）。这是最容易犯的错，因为 `ProbMap` 里到处都是 `sc_.resolution`。
4. **盒外的 `distance_buffer` 是陈旧值，`resetLocalMap` 也不清它**（`esdf_map.cpp:66-70`）。滑窗走过之后那里留的是上一个地点的距离。**这是本方案最阴险的一处**——不会崩、不会报错，只是距离场在某些区域是错的。
5. **`esdf/local_update_box` 不写会抛异常**（`config.hpp:84-94`），而且报错信息是 `"Fix map origin size is not 3!"`——**和参数名对不上，别被误导**，那就是这一项缺了。
6. **`scan_z_max_rel` 是"会不会撞车"的那个参数。** 它必须 ≥ 车高 + 余量。**调小了会撞车，不是精度问题。** 摆实物横杆标定（§5.4 D3）。
7. **线程安全。** `vizCallback` 和 `updateCallback` 是不同定时器线程（`rog_map_ros1.hpp:151/116`）。`buildField2D` 写 `field_`、`vizCallback` 读 `field_` → `Field2D` 里已加锁（§4.2）。但 `buildField2D` 读 `distance_buffer` 时若与 `updateESDF3D` 并发，会读到中间态——`updateESDF3D` 自己有 `update_esdf_mtx`（`esdf_map.h:86`），**但 `getDistance` 不加锁**。正式做要加锁（参考 `update_esdf_mtx` 的用法）。
8. **首帧大片 UNKNOWN。** 首帧会做一次"清空机器人周围未知"（`prob_map.cpp:358-374`），刚启动时到处是未知，`d_2D` 可能是 `far_distance`。**属正常现象**，等几秒。
9. **`Field2D::evaluate` 的 `floor` vs `round`。** 与 `ORIGIN_AT_*` 宏必须一致，否则整体错半格（§4.2 末）。
10. **odom 的 z 和地图 z 范围要匹配。** `esdf/local_update_box` 是 odom 居中的，而地图 z 范围由 `map_size.z` / `fix_map_origin` 定。RM 车贴地（odom z ≈ 0）和仿真无人机（z ≈ 1.5）要用不同的 `fix_map_origin` / `map_size`，否则扫描带整个落到地图外。

### 11.0 为什么测试和工作顺序是绑在一起的

### 11.2 A 组：`reduceMinZ`（对应 ①）

**这一组是硬门槛。** 它不过，后面全无意义。

```cpp
using namespace rog_map;

// A1 min 语义：取最小值，不管它在哪一层
static void a1_min_semantics() {
    const MinZConfig cfg;
    {
        std::vector<double> col{3.0, 2.0, 0.4, 1.1};
        const auto r = reduceMinZ(col, cfg);
        assert(r.valid && !r.blocked);
        assert(near(r.distance, 0.4));
        assert(r.n_sampled == 4 && r.n_blocked == 0);
    }
    {
        // 顺序无关
        std::vector<double> col{0.4, 1.1, 3.0, 2.0};
        assert(near(reduceMinZ(col, cfg).distance, 0.4));
    }
    {
        // 极小值在最高层 —— min 照样取到（对应"天花板以下能过"不能只看低层）
        std::vector<double> col{5.0, 4.0, 3.0, 0.2};
        assert(near(reduceMinZ(col, cfg).distance, 0.2));
    }
    ok("a1_min_semantics");
}

// A2 符号与 blocked：只要有一个负值就 blocked，且 d_2D 为负
static void a2_sign_and_blocked() {
    const MinZConfig cfg;
    {
        std::vector<double> col{2.0, 1.5, -0.1, 1.2, 2.0};
        const auto r = reduceMinZ(col, cfg);
        assert(r.valid && r.blocked);
        assert(r.n_blocked == 1);
        assert(near(r.distance, -0.1));
    }
    {
        // 多个负值 → 取最负的
        std::vector<double> col{-0.1, -0.5, -0.2};
        const auto r = reduceMinZ(col, cfg);
        assert(r.blocked && r.n_blocked == 3);
        assert(near(r.distance, -0.5));
    }
    {
        // 恰好 0：不算 blocked（< 0 才判），d_2D = 0 → 贴墙
        std::vector<double> col{1.0, 0.0, 1.0};
        const auto r = reduceMinZ(col, cfg);
        assert(!r.blocked);
        assert(near(r.distance, 0.0));
    }
    ok("a2_sign_and_blocked");
}

// A3 退化输入（最容易崩的地方）
static void a3_degenerate() {
    const MinZConfig cfg;
    {
        // 空柱 → valid=false，走 far_distance 兜底
        std::vector<double> col{};
        const auto r = reduceMinZ(col, cfg);
        assert(!r.valid && !r.blocked);
        assert(near(r.distance, cfg.far_distance));
    }
    {
        // 全 NaN / Inf → 等同空柱（这是真实场景：更新盒边缘取到无效值）
        std::vector<double> col{std::nan(""), std::nan("")};
        assert(!reduceMinZ(col, cfg).valid);

        std::vector<double> col2{std::nan(""), 1.7, std::nan("")};
        const auto r = reduceMinZ(col2, cfg);
        assert(r.valid && r.n_sampled == 1);
        assert(near(r.distance, 1.7));
    }
    {
        // 单元素
        std::vector<double> col{-0.05};
        const auto r = reduceMinZ(col, cfg);
        assert(r.blocked && near(r.distance, -0.05));
    }
    ok("a3_degenerate");
}

// A4 clamp 与 inflation
static void a4_clamp_inflation() {
    {
        // clamp：超出 max_distance 被截断
        MinZConfig cfg;
        cfg.max_distance = 6.0;
        cfg.clamp_distance = true;
        std::vector<double> col{50.0};
        assert(near(reduceMinZ(col, cfg).distance, 6.0));

        // 负值也被 min_distance 截断
        std::vector<double> col_neg{-100.0};
        assert(near(reduceMinZ(col_neg, cfg).distance, -3.0));
    }
    {
        // 不 clamp：原值透出
        MinZConfig cfg;
        cfg.clamp_distance = false;
        std::vector<double> col{50.0};
        assert(near(reduceMinZ(col, cfg).distance, 50.0));
    }
    {
        // inflation：整体平移（正负一起往负方向走）
        MinZConfig cfg;
        cfg.inflation_radius = 0.2;
        std::vector<double> col{1.0};
        assert(near(reduceMinZ(col, cfg).distance, 0.8));

        // 原本 +0.1（贴墙可过）→ 膨胀后 -0.1（不可过）。这就是给车留安全边界的机制。
        std::vector<double> col2{0.1};
        const auto r = reduceMinZ(col2, cfg);
        assert(near(r.distance, -0.1));
        assert(!r.blocked);        // ⚠️ blocked 是"原始柱内有负值"，**不受 inflation 影响**
    }
    ok("a4_clamp_inflation");
}
```

> **A4 的最后一条是个设计决策，你要想清楚**：`blocked` 反映的是"原始 3D ESDF 说这里相交"，而 `distance` 已经含 `inflation_radius`。所以**发布占据栅格时，判断该用哪个要明确**：
> - `occ[i] = blocked` → 障碍只膨胀在**距离值**上，栅格本身不膨胀 → costmap 自己会按距离生成代价
> - `occ[i] = (distance < 0)` → 障碍栅格本身按 `inflation_radius` 膨胀
>
> **§6.1 的代码用的是后者**（`occ[i]` 由 `blocked` 赋值，但 `distance` 已经含 inflation），两处语义要对齐。建议统一成"`occ` 用原始 `blocked`，inflation 只体现在距离里"，这样 costmap 能自由选膨胀层。

### 11.3 B 组：`Field2D`（对应 ①）

**B1 栅格排布（行优先，y-major）**

```cpp
static void b1_grid_layout() {
    const int W = 4, H = 3;
    const double res = 0.1;
    std::vector<double>  dist(W * H, 0.0);
    std::vector<uint8_t> occ(W * H, 0U);

    dist[0 * W + 0] = 1.1;          // (i=0, j=0)
    dist[2 * W + 3] = -0.2;         // (i=3, j=2)
    occ[2 * W + 3]  = 1U;

    Field2D f;
    f.update(W, H, res, Eigen::Vector2d(1.0, 2.0), dist, occ);

    assert(f.width() == W && f.height() == H);
    assert(f.origin().x() == 1.0 && f.origin().y() == 2.0);

    const auto &d = f.distances();
    assert(near(d[2 * W + 3], -0.2));                // 行优先：j*W + i
    assert(f.occupied()[2 * W + 3] == 1U);
    ok("b1_grid_layout");
}
```

**B2 `evaluate` 的坐标换算与边界**

```cpp
static void b2_evaluate_bounds() {
    const int W = 4, H = 3;
    const double res = 0.1;
    std::vector<double>  dist(W * H, 5.0);
    std::vector<uint8_t> occ(W * H, 0U);
    dist[2 * W + 3] = -0.2;
    occ[2 * W + 3]  = 1U;

    Field2D f;
    f.update(W, H, res, Eigen::Vector2d(1.0, 2.0), dist, occ);

    double d = 0.0;
    // 格 (i=3, j=2) 占 [1.3,1.4) × [2.2,2.3)，格心 1.35 / 2.25
    assert(f.evaluate(Eigen::Vector2d(1.35, 2.25), d));
    assert(near(d, -0.2, 1e-6));

    // floor 语义：左闭右开。落在 (1.30, 2.20) 还在这一格
    assert(f.evaluate(Eigen::Vector2d(1.30, 2.20), d));
    assert(near(d, -0.2, 1e-6));

    // 越界（右下两面）
    assert(!f.evaluate(Eigen::Vector2d(0.9, 2.0), d));
    assert(!f.evaluate(Eigen::Vector2d(1.4, 2.0), d));
    assert(!f.evaluate(Eigen::Vector2d(1.0, 2.3), d));
    assert(!f.evaluate(Eigen::Vector2d(1.0, 1.9), d));

    // 未 update 过 → 直接 false，不能崩
    Field2D empty;
    assert(!empty.evaluate(Eigen::Vector2d(0.0, 0.0), d));
    ok("b2_evaluate_bounds");
}
```

### 11.6 E 组：性能（对应 ⑤）

见 §7.1 的打点代码。

```cpp
TimeConsuming t_esdf("updateESDF3D", false);
esdf_map_->updateESDF3D(pos);
double dt_esdf = t_esdf.stop();

TimeConsuming t_proj("buildField2D", false);
buildField2D();
double dt_proj = t_proj.stop();
```

**验收**：`dt_proj` 应远小于 `dt_esdf`（预期 < 1 ms vs 几 ms）。**如果 `dt_proj > dt_esdf`，说明你把归约写在了错误的地方**（比如每格重复调用了 `getUpdatedBbox`，或者每格都在 `push_back` 一个没 `reserve` 的 vector）。

| 对应 | 测试 | 通过判据 | 失败时先查 |
